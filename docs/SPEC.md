# photo-upscaler 仕様書（v0.1 確定版）

## 1. 目的
画質の悪い人物写真やネット・LINEで受け取った画像を、AIで復元・拡大し、
**セブン-イレブンの写真プリント（2L判）** できれいに印刷できるようにする。
自分一人で使う個人用アプリ（人に配らない・お金をもらわない）。

## 2. 対象の画像（想定）
- 人物の写真（全身・上半身）、強く圧縮された小さい画像
- 例：670×2576 px（横:縦 ≒ 1:3.8）。ピクセル数は足りているが、ぼやけ・JPEGの圧縮ノイズ・顔のつぶれがある
- → 必要なのは「拡大」よりも **復元（ぼやけと圧縮ノイズを取って、くっきりさせる）** が中心

## 3. 動かす環境
- iPad Air 11インチ（M3、メモリ8GB）の Safari。ホーム画面に追加して使う（PWA）
- Webアプリ：WebGPU ＋ ONNX Runtime Web（WebGPUが使えない場合はWASM）
- **画像はiPadの外に送らない**（処理はすべて端末の中で行う）
- 置き場所：新しい公開リポジトリ `photo-upscaler` ＋ GitHub Pages
- AIのデータはこのリポジトリに入れて、GitHub Pages から同じ場所として読み込む（外部の配布サイトに頼らない）
  - Real-ESRGAN x4plus：公式の重み（.pth）を `tools/export_realesrgan_onnx.py` で ONNX に変換したもの（約67MB）
  - ONNX Runtime Web 1.31.1：`vendor/ort/`（WebGPU版。WebGPUが使えなければWASMで動く）
  - 1回読み込んだら iPad に保存（Cache Storage）し、2回目からは読み込まない
- AIの計算は別スレッド（Web Worker）で行い、処理中も画面が固まらないようにする

## 4. 画面の流れ（1枚ずつ）
1. 写真を選ぶ（写真ライブラリ／ファイル）
2. 切り抜く
3. AI処理（進み具合を表示）
4. 補正前と比べる・顔補正の強さを調整する
5. 写真アプリに保存

## 5. 切り抜き・レイアウト
- 切り抜き枠は、書き出すサイズの比率に固定し、自由に動かせる・ピンチで拡大縮小できる
- 最初は「全身が入る位置」（画像全体がおさまる大きさで、中央）
- 余白は**元の写真を大きくぼかして敷いた背景**で埋める
- フチなし印刷で端が切れたときの目安線（外側から約2〜3mm）を表示する（書き出しには含めない）

## 6. 書き出すサイズ
| サイズ | mm | px（300dpi） | 備考 |
|---|---|---|---|
| **2L判（初期値）** | 127×178 | 1500×2102 | メイン |
| L判 | 89×127 | 1051×1500 | 画質が足りないとき用 |
| はがき | 100×148 | 1181×1748 | ほかの印刷サービス用 |

- 縦向きと横向きを切り替えられる
- 形式：JPEG（品質0.95）、sRGB。印刷用に300dpiの情報を書き込む

## 7. AIの処理
### 7.1 拡大・復元
- 切り抜いた範囲を、本来の画質相当の大きさまで一度縮小してから、**Real-ESRGAN x4plus（写真用）** で4倍に拡大し、書き出すサイズに合わせる
- 縮小は「しない／1/2／1/3（初期値）／1/4」から選ぶ。サンプル画像で比べた結果、1/3 が一番自然だったため初期値にした
- AIに渡す倍率 ＝ min(1, 1/縮小, 書き出し倍率÷2)。書き出しに必要な大きさの2倍を超える分は計算しない（大きな写真で時間がかかりすぎないように）
- 4倍の大きな画像は作らず、タイルごとに書き出しの解像度へ縮小して描く（Safari のキャンバスの上限対策）
- AI処理のあとで位置・サイズ・向き・縮小を変えたら、結果は使わず、もう一度処理してもらう
- 画像を小さく分けて（タイル＋のりしろ16px）処理し、Safariのメモリ不足を防ぐ
  - WebGPU には1つのデータの大きさに上限がある（iPad で 256px タイルが失敗した。一番大きな中間データは「(タイル＋32)×4 四方 × 64層 × 4バイト」）
  - タイルの大きさは GPU の上限から自動で決める。失敗したらタイルを半分にしてやり直し、48px でも失敗したら WASM でやり直す
  - iPad では、WebGPU がエラーを出さずに真っ黒な結果を返し、同時に画面の画像（元の写真）まで消えることがあった（GPU 側が落ちたと思われる）
    - AI の結果が真っ黒・計算不能な値なら失敗とみなしてやり直す
    - AI の結果を描くキャンバスは CPU 側に置く（`willReadFrequently`）。元の写真が消えていたらファイルから読み込み直す
    - WebGPU は 96px 以下のタイルで始める
  - 「処理：自動／GPU（速い）／CPU（確実・遅い）」を選べる（端末に保存）。自動で GPU が失敗したら、次からも CPU を使う
  - CPU（WASM）は複数のコアを使う（4スレッド）。GitHub Pages ではヘッダーを付けられないため、`coi-serviceworker.js` で cross-origin isolated にする
  - 試験用に `?debug=gpufail` / `?debug=gpufailall` / `?debug=gpuzero` で失敗をまねられる

### 7.2 顔補正
- 処理した範囲から顔を自動で見つける（RetinaFace mobilenet0.25、約1.7MB）。長い辺を 1024px まで縮小して探す。複数の顔もまとめて補正する
- 両目・鼻・口の両端の5点から、顔を 512×512 にそろえて元の写真から切り出す（CodeFormer と同じ基準の位置）
- **CodeFormer** で補正する（個人利用なので、S-Labライセンスの条件の範囲内）
  - 重みは float16 で保存（約189MB）。GitHub の1ファイル100MBの上限のため2つに分けて置き、読み込むときにつなげる
  - 中間データが大きく iPad の GPU では不安定なため、いつも CPU（WASM、4スレッド）で動かす
- 画面の下の「顔を補正」でオン／オフ、スライダー（きれいさ 0 〜 1 本人らしさ）で強さを変えられる。**初期値は 0.7（本人らしさ寄り）**
  - 強さを変えたときは、顔の補正だけをやり直す（高画質化はやり直さない）
- 補正した顔は、縁をぼかした四角で元の位置に貼り戻す

## 8. 補正前と比べる画面
- 真ん中の線を左右に動かして、補正前と後を見比べる
- ピンチで拡大して、顔や細かいところを確認できる

## 9. 性能の目安
- 2L判1枚：約30秒〜1分（M3＋WebGPU）
- 初めて使うときだけ、AIのデータ（約400MB）を読み込む

## 10. 最初の版で作らないもの
まとめて複数枚の処理／文字入れ／顔ごとの個別調整／AIで背景を描き足す機能／イラスト用モデル／ネイティブアプリ版

## 11. 作る順番
1. 写真を選ぶ・切り抜く・ぼかした余白・書き出し（AIなし）
2. Real-ESRGAN（小さく分けて処理する、WebGPU）
3. 顔検出＋CodeFormer＋強さのスライダー
4. 補正前と比べる画面・PWA化・AIデータの保存
5. セブン-イレブンで試し印刷 → 調整
